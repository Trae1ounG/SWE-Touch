Benchmarking Coding Agents When Users Touch the Code

SWE-Touch evaluates whether coding agents can continue a software repair after a user has changed the shared repository state.

View code Browse dataset

Why SWE-Touch?

Interactive coding benchmarks largely model user participation as messages. SWE-Touch adds a stronger form of interaction: a user edit changes the executable workspace that the agent must subsequently read, test, and repair.

Evaluation protocol

One shared workspace, two authors

The task, checkout, tools, budget, and verifier remain fixed. Only the user-authored edit changes the live repository state.

Key result

Autonomous success does not guarantee recovery after a user edit.

All resolve rates are percentages. The main SWE-bench Verified results report mean ± standard deviation over repeated runs.

  • −7.7mean resolve-rate changeEvery evaluated model declines under Counter-Edit on SWE-bench Verified.
  • 1.3–16.5points lost across modelsThe effect varies sharply despite an identical evaluation protocol.
  • 63.3%retained-conflict failuresMost failed runs terminate with the conflicting user behavior still active.
